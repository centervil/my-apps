# Requirements: Issue #183 - Spotify 自動化の堅牢化

## 概要
Spotify ポッドキャストエピソードの自動アップロード機能（`spotify-automation`）を無人実行（ヘッドレス/CI運用）でより堅牢にするため、以下の3点を実装する。

## 要件
1. **セッション維持・検証（Session Verification）**
   - アップロード実行前に、保存済みのログイン状態（セッション/Cookie/LocalStorage）が有効かどうかを詳細に検証する。
   - 単なるファイル存在確認だけでなく、有効期限切れやセッション無効状態を「ログイン切れ (`EXPIRED_AUTH` / `INVALID_SESSION`)」として通常のアップロードエラーと明確に区別し、非ゼロの終了コードおよび明確なステータスで即座に失敗させる。
2. **失敗の検知とリトライ機構（Retry with Error Classification）**
   - 一時的な失敗（ネットワーク切断、要素の読み込みタイムアウト等）は、上限回数（例: 最大3回）を設定して指数バックオフ等でリトライする。
   - 恒常的な失敗（認証切れ、不正な設定、ファイル不存在等）はリトライせず即座に検知してプロセスを停止する。
3. **機械可読な実行結果報告と終了コード（Result Reporting & Exit Codes）**
   - 実行結果（成功／失敗、失敗理由、エラーコード、タイムスタンプ、詳細メッセージ）を機械可読な JSON 形式で出力する（ファイル出力および標準出力への構造化ログ）。
   - 終了コードにより成否が厳密に判別できるようにする（成功: 0, 一時エラー/失敗: 1, 認証切れ: 2 等の明確な区分け、または標準仕様に準拠）。

## 受け入れ基準 (Acceptance Criteria)
- 認証切れの状態で実行した場合、セッション切れとして検知され、リトライされずに即時終了する。
- 一時的エラー（タイムアウト等）の場合、設定された上限までリトライが行われること。
- 実行終了時に JSON レポートが生成され、CIや上位スクリプトから成否が判断できること。
- 既存のユニットテスト・E2Eテストがすべて成功し、新しいロジックに対するユニットテストが追加されていること。
