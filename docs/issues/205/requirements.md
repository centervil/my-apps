# Issue 205: note CLI に公開ステップを追加する

## 概要
現在の note CLI (`src/noteCli.ts`) は下書きの作成と品質チェック（3点確認）までをサポートしているが、本Issueでは実際に note 記事を一般公開するフロー（公開ステップ）を追加する。

## ユーザー要件 (Requirements)
1. **CLI オプションの追加**:
   - `--publish`: boolean（デフォルト `false`）。指定された場合、品質チェック通過後に公開処理へ進む。
   - `--tags`: string（カンマ区切り、'#' の有無は両対応）。公開設定でのハッシュタグ入力に使用。
   - `--magazine`: string（マガジン名）。公開設定でのマガジン追加に使用。
2. **ヘッダー画像設定**:
   - `--previousNoteId` が指定されている場合、note API (`https://note.com/api/v3/notes/<id>`) から eyecatch 画像 URL を取得し、ダウンロードしてエディタのヘッダー画像として設定する。失敗しても公開は止めず、結果 JSON に成否を記録する。
3. **公開フローの実装**:
   - 実際の note エディタの画面遷移・UIに合わせて実装する。
   - 下書き編集画面（`editor.note.com/notes/<id>/edit/`）で品質チェックを通した後、「公開に進む」（またはそれに該当するボタン）をクリックし、公開設定モーダル等でハッシュタグ、マガジン、価格（無料）を設定し、投稿／公開ボタンを実行する。
4. **品質チェック不合格時の挙動**:
   - 品質チェックが1点でも落ちた場合は、公開画面へ進まず、結果 JSON の `status` を区別できる値（例：`QUALITY_CHECK_FAILED`）にし、終了コード `1` を返して終了する。
5. **成功時の結果 JSON**:
   - 公開まで成功した場合、公開 URL（`https://note.com/clever_chives813/n/<id>` 形式）と note ID を含める。
6. **後方互換性と他機能への影響維持**:
   - `--publish` なしの従来実行が下書きまでで止まることを保証する。
   - Spotify 側（`src/cli.ts`）は変更しない。新規 npm 依存は追加しない。
