# Requirements: Issue #210 - note CLI 本文変換の従来体裁一致

## 目的
note CLI の本文変換を従来フロー（手動の貼り付け作成）と体裁一致させる。

## ユーザーストーリー
- 開発者として、note CLI を用いて生成・公開する記事の本文が、手動の従来フローと同等の美しい体裁（目次ブロック、正しい見出し、箇条書き `<ul>/<li>`、番号付きリスト `<ol>/<li>`、`<strong>`、適切な空段落制御）になるようにしたい。
- 自動品質チェックによって、不完全な体裁やリテラル残存、目次未挿入の記事が公開されないようにしたい。

## 受け入れ基準
1. **クリップボード HTML 貼り付け**: `NoteEditorPage.setBodyAndEmbed` において、`navigator.clipboard.write` と `Ctrl+V` を用いて markdown から変換した HTML を貼り付ける。
2. **markdown→HTML 純粋関数 (`convertMarkdownToHtml`)**:
   - 最初の `## 📚` → `<h3>`
   - 他の `##` → `<h2>`
   - `###`/`####` → `<h3>`
   - `* ` / `- ` → `<ul><li>...</li></ul>`
   - `N. ` → `<ol><li>...</li></ul>`
   - `**x**` → `<strong>`
   - 空行はブロック区切り（空段落を作らない）
   - 段落の直後に空行なしで続く番号付きリストもリストとして処理
   - 連続する通常行は1つの段落に `<br>` でつなぐ
   - 太字のみの行やリスト項目の正確な変換
3. **見出し修復**: 貼り付け後、先頭の見出しブロックが段落に潰れている場合、その段落の先頭にカーソルを置き `### ` とタイプして見出し化する（少なくとも最初の見出しが正しい要素になっているか DOM 確認）。
4. **目次ブロックの挿入**: テキストが「目次」と完全一致する可視要素（挿入メニュー等）をクリックして実ブロックを挿入し、DOM 内に目次要素（`table-of-contents` 相当）が存在することを確認。
5. **定型文と Spotify URL**: 現行方式（タイプ＋Enter）を維持。
6. **品質チェック強化 (`performQualityCheck` / エディタ側)**:
   - 目次チェックは目次ブロック要素の存在 (`table-of-contents` 等)
   - リテラル `**` が本文に残っていないこと
   - `li` のテキスト先頭に `* ` / `- ` が残っていないこと
   - 番号付きリスト素材がある場合、レンダリング結果に `<ol>` が存在すること
   - 空段落 (`<p><br></p>` 相当) の数が閾値以下（5以下）
   - いずれか欠ければ `passed=false`
7. **単体テスト**: `convertMarkdownToHtml` のテスト（見出しマッピング、ul/ol、strong、空行、段落直後の番号付きリスト、太字のみの行）を追加し、既存テストも全てパスする。
